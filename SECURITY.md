# Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Until a dedicated security mailbox is published, use GitHub private
vulnerability reporting for this repository. Include affected versions,
reproduction steps, impact, and any suggested mitigation.

## Security scope

High-priority reports include:

- Device-certificate or authentication bypass.
- Remote code execution through a connector, model manifest, or managed engine.
- Host filesystem or credential exposure.
- Sandbox or container escape.
- Prompt, completion, or API-key persistence.
- Forged usage, replayed jobs, or earnings manipulation.
- Unsafe auto-update or release-signature behavior.

The project does not claim that ordinary community hardware provides
confidential inference.
